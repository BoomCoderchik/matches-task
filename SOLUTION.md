# Решение

## Сколько заняло

Около 35 минут, включая чтение задания, установку зависимостей и браузерные проверки.

## Что сделано и что не успел

Все три обязательные части: загрузка по HTTP, список с командами, счётом, локальным временем и русскими статусами; загрузка, ошибка с повтором, пустой ответ; фильтры, обновление, избранное и работающий таймер. При неудачном обновлении остаются прежние матчи и время последней успешной загрузки. Запрос отменяется при размонтировании, ограничен 15 секундами; ответ проверяется перед отображением.

Дополнительно — поиск по обоим клубам без учёта регистра и тесты фильтрации. Поиск полезен на длинном списке и сочетается с фильтром. Playwright добавлен только как devDependency для воспроизводимых браузерных проверок.

После первого просмотра переработан дизайн: единый список вместо сетки карточек, общая ось счёта, компактные фильтры и один акцент для текущего матча. Roboto Condensed хранится локально с лицензией OFL; `expo-font` нужен для его загрузки, `react-native-svg` — для трёх согласованных иконок. Обе библиотеки установлены через Expo CLI под SDK 57, включены в Expo Go и не требуют development build.

Телефон с Expo Go не проверялся. Веб-интерфейс проверен в Chromium на ширинах 320, 390, 678 и 1280 px; нативные компоненты и исходный стек сохранены.

## Решения

- «Предстоящие» — `scheduled` и `postponed`: перенесённая игра ещё должна состояться. «Завершённые» — только `finished`. Текущие `live` и неизвестные статусы доступны во «Все»; неизвестный статус обозначается как «Статус уточняется».
- Фильтрую по статусу сервера, а не по дате: в исходных данных дата уже может быть в прошлом, хотя статус остаётся `scheduled` или `live`.
- `0 : 0` — существующий счёт. Отсутствующий счёт показываю как `— : —`, а `startsAt: null` и нераспознаваемую дату — как «Дата и время уточняются». Не преобразую `null` в 1970 год. Минуту `0` тоже не теряю.
- `Intl.DateTimeFormat` использует часовой пояс устройства без фиксированного смещения; в карточке есть и дата, и время. У матчей стабильные ключи по `id`; повторяющиеся `id` и некорректная структура ответа приводят к ошибке, а не скрытой потере строк.
- В `MATCHES_URL` шаблон содержал буквальные `OWNER/REPO`, несмотря на комментарий «Адрес менять не нужно». Заменил их на `Interlabs22/test-app`: это тот же исходный файл, доступный по настоящему HTTP-адресу. Локальный JSON не подставляется вместо сетевого запроса.

## Баги из части 2

1. Звёздочки: `indexOf` возвращает `-1` для отсутствующего элемента и `0` для первого найденного; `Boolean(-1)` равно `true`, а `Boolean(0)` — `false`, поэтому проверка работала наоборот. `push`/`splice` меняли исходный массив, затем в React передавалась та же ссылка, из-за чего обновление могло пропускаться. Заменил проверку на `includes`, а переключение — на функциональное обновление с новым массивом.
2. «Обновлено N сек назад»: интервал с пустыми зависимостями захватывал начальный `seconds = 0` и каждый раз записывал `1`; `since` вообще не использовался, интервал не очищался. Теперь число секунд считается как разница `Date.now()` и `since`, эффект перезапускается при новом времени успешной загрузки и очищает интервал при размонтировании.

## Как я использовал ИИ

Реализацию и проверки выполнил ИИ-агент. Проверка результата владельцем репозитория ещё не подтверждена; автоматически проверены типы, логика, браузерные сценарии и веб-сборка, отдельно просмотрены скриншоты четырёх размеров.

Неполное решение обнаружилось на проверке доступности: одного `accessibilityState` оказалось недостаточно для установленного React Native Web — в HTML не было выбранного состояния. Браузерный тест это выявил; добавлены `aria-selected` для вкладок и `aria-pressed` для веб-версии звёздочки, нативное состояние сохранено. Ещё первый запуск typecheck был сделан до окончания `npm install`: использовался старый глобальный компилятор; повторная проверка локальным TypeScript прошла.

Проверки воспроизводятся командами `npm run typecheck`, `npm test`, `npx playwright install chromium`, `npm run test:web`, `npm run build:web`. В основном браузерном сценарии используется настоящий HTTP-источник; пустые ответы, ошибки и повреждённый JSON подменяются только внутри тестов.

`npm audit --omit=dev` сообщил о 18 уязвимостях исходного дерева зависимостей (15 high, 3 moderate). Автоматический `--force` предлагает смену основных версий Expo / React Native, поэтому в рамках задания такой откат не выполнялся.

## Что улучшил бы, будь ещё 2 часа

Проверил бы Expo Go на iOS и Android, добавил сохранение избранного через совместимое с Expo Go хранилище и расширил проверки запросов на таймаут и конкуренцию. Отдельно разобрал бы advisory исходных зависимостей и проверил безопасные совместимые обновления.
